# home/ — configs

Every folder here is a **Stow package**: its contents mirror `$HOME`, and `make link`
symlinks them into place. Edit the files through their normal paths (`~/.zshrc`,
`~/.config/tmux/tmux.conf`, …); you are editing this repo.

| Package | Links | Customize in |
| --- | --- | --- |
| [`zsh`](#zsh) | `~/.zshrc`, `~/.zprofile`, `~/.p10k.zsh`, `~/.config/zsh/` | modules, `~/.zshrc.local`, `~/.zprofile.local` |
| [`git`](#git) | `~/.config/git/config`, `~/.config/git/ignore` | `~/.config/git/config.local` |
| [`tmux`](#tmux) | `~/.config/tmux/tmux.conf` | the file itself |
| [`ghostty`](#ghostty) | `~/.config/ghostty/config.ghostty` | the file itself |
| [`nvim`](#neovim) | `~/.config/nvim/` | [its own README](nvim/.config/nvim/README.md) |
| [`conda`](#conda) | `~/.condarc` | the file itself |
| [`claude`](#claude-code) | `~/.claude/settings.json` | the file itself |
| [`bin`](#bin) | `~/.local/bin/tmux-sysinfo` | add scripts |

Codex has no linked files: its `~/.codex/config.toml` is seeded once, see [Codex](#codex).

**Contents:** [How linking works](#how-linking-works) · [Machine-local files](#machine-local-files) ·
[Add, remove or rename a package](#add-remove-or-rename-a-package) · per-package sections below.

## How linking works

- **Folded packages** (`nvim`, `tmux`, `ghostty`, `zsh`): Stow may link a whole directory,
  e.g. `~/.config/nvim → ~/dotfiles/home/nvim/.config/nvim`. New files you create in it
  land in the repo automatically.
- **Per-file packages** (`git`, `claude`, `conda`, `bin`): only tracked files are
  linked, because those directories also hold machine-local or app-owned files
  (`config.local`, agent logins/history, other binaries in `~/.local/bin`).
- The split is set by `FOLDED` / `PER_FILE` in [`setup/link.sh`](../setup/link.sh).
- Before linking, real files in the way are moved to `~/.dotfiles-backup/<time>/`.
- Some apps save by replacing the link with a new file. `make doctor` shows those as
  "not linked": copy the change into the repo file, delete the stray file, `make link`.

## Machine-local files

Untracked (`*.local` is gitignored) and loaded automatically when present. Use them for
anything private or specific to one machine.

| File | Loaded by | Typical content |
| --- | --- | --- |
| `~/.config/git/config.local` | git `[include]` | name, email, signing key, per-directory identities |
| `~/.zprofile.local` | end of `.zprofile` | extra `PATH`, machine-specific env vars |
| `~/.zshrc.local` | `.zshrc`, before the prompt | private aliases/functions, secrets from a password manager |

## Add, remove or rename a package

```sh
# add: move an existing config in, mirroring its path under $HOME
mkdir -p home/foo/.config/foo
mv ~/.config/foo/config.toml home/foo/.config/foo/
# then add "foo" to FOLDED or PER_FILE in setup/link.sh
make link && make doctor

# remove: unlink, take the files back, delete the package
stow --dir=home --target="$HOME" --delete foo
cp -R home/foo/.config/foo ~/.config/    # if you still want the config
git rm -r home/foo                       # and drop "foo" from setup/link.sh
```

Don't put README or other non-config files inside a package: everything in it is meant to
be linked into `$HOME`. Document packages in this file instead.

## zsh

| File | Runs for | Contains |
| --- | --- | --- |
| `.zprofile` | login shells (every terminal tab, tmux pane via `zsh -l`) | Homebrew env, `GOPATH`, `NVM_DIR`, `PNPM_HOME`, Android/Java (macOS), `PATH` |
| `.zshrc` | interactive shells | fastfetch, Powerlevel10k, completion, loads `~/.config/zsh/*.zsh`, `~/.zshrc.local` |
| `.config/zsh/options.zsh` | | history, `AUTO_CD`, key bindings, fzf |
| `.config/zsh/aliases.zsh` | | `EDITOR`, named directories, git aliases |
| `.config/zsh/toolchains.zsh` | | nvm, conda/mamba, zoxide |
| `.config/zsh/tproj.zsh` | | `tproj` tmux project sessions |
| `.p10k.zsh` | | Powerlevel10k prompt layout (generated by `p10k configure`) |

**Customize**

- **Add an alias / function:** shared → `aliases.zsh` (or a new module); private →
  `~/.zshrc.local`. Modules load alphabetically; any `*.zsh` file you add is picked up.
- **Named directories:** `hash -d name=/path` in `aliases.zsh`, then `cd ~name` or just `~name`.
- **PATH:** add to the `path=(…)` list in `.zprofile` (non-existent dirs are dropped
  automatically), or per machine in `~/.zprofile.local`.
- **Prompt:** run `p10k configure`; it rewrites `~/.p10k.zsh` (the repo file).
- **Turn off fastfetch:** delete its block at the top of `.zshrc`.
- **Vi mode in the shell:** uncomment `bindkey -v` in `options.zsh`.
- **History size:** `HISTSIZE` (in memory) / `SAVEHIST` (on disk) in `options.zsh`.
- **`tproj` windows:** edit the `code` / `claude` / `codex` blocks in `tproj.zsh`
  (each is created only if missing, so existing sessions are safe).
- **Startup time:** `time zsh -lic exit`; nvm and conda are the largest costs.
  Don't run `conda init` — `toolchains.zsh` already does its job.

## git

`config` holds shared defaults and includes `~/.config/git/config.local` for identity.

| Setting | Value | Effect |
| --- | --- | --- |
| `core.editor` | `nvim` | commit messages in Neovim |
| `core.autocrlf` | `input` | never commit CRLF |
| `init.defaultBranch` | `main` | |
| `push.autoSetupRemote` | `true` | first `git push` sets upstream |
| `fetch.prune` | `true` | deleted remote branches disappear locally |
| `diff.algorithm` / `colorMoved` | `histogram` / `default` | clearer diffs, moved lines colored |
| `merge.conflictStyle` | `zdiff3` | conflicts show the common ancestor |
| `rerere.enabled` | `true` | git remembers how you resolved a conflict |

`ignore` is the global ignore file (agent files: `AGENTS.md`, `CLAUDE.md`, `.claude`,
`.codex`, `.claudeignore`). Remove a line there if you want to commit those in your projects.

**Customize identity** in `~/.config/git/config.local` (created by `make git`). Different
identities per folder, e.g. work repos vs. personal:

```ini
[user]
	name = Your Name
	email = you@example.com
[includeIf "gitdir:~/Workspace/work/"]
	path = ~/.config/git/work.local
```

```ini
# ~/.config/git/work.local
[user]
	email = me@company.example
```

Signing commits: add `[user] signingkey = …` and `[commit] gpgsign = true` to the same file.

## tmux

One file: `.config/tmux/tmux.conf`. Reload after editing with `Ctrl+B r` or `make tmux-reload`.

| Section | What to change |
| --- | --- |
| Prefix | `set -g prefix C-b` (e.g. `C-a`; also `unbind C-b` and `bind C-a send-prefix`) |
| Basics | mouse, history limit, window numbering, `escape-time` |
| Copy mode | vi keys; copies go to the system clipboard via OSC 52 |
| Appearance | Catppuccin Mocha colors for status bar, tabs, borders, messages |
| Status right | `#(~/.local/bin/tmux-sysinfo)` + clock; `status-interval` sets refresh |
| Titles | `set-titles-string "#S · #W"`: Ghostty tabs show session and window |
| Passthrough | `allow-passthrough all` lets Claude Code / Codex notifications reach Ghostty from background windows |
| Navigation | `Ctrl+h/j/k/l` shared with Neovim (smart-splits); change both sides together |
| Clear screen | `Ctrl+B Ctrl+L` (because plain `Ctrl+L` navigates); Ghostty sends it on `Cmd+K` |
| Sessions survive a reboot | resurrect + continuum, see below |

**Common tweaks**

- New split bindings in the current directory:
  ```tmux
  bind-key | split-window -h -c "#{pane_current_path}"
  bind-key - split-window -v -c "#{pane_current_path}"
  ```
- Pane navigation on `Alt+h/j/k/l` instead (frees `Ctrl+L` for clearing): change the four
  `bind-key -n C-…` lines to `M-…` **and** the keys in `nvim/…/plugins/smart-splits.lua`.
- Different theme: replace the hex colors in the Appearance section.

**Sessions survive a reboot**

[tmux-continuum](https://github.com/tmux-plugins/tmux-continuum) saves all sessions every
10 minutes with [tmux-resurrect](https://github.com/tmux-plugins/tmux-resurrect) and
restores them when the tmux server starts. After a reboot, run `tmux` once: it brings back
every session, window, split, directory and the visible pane contents, replacing the empty
session it started with. Plain `tmux attach` can't start the server, so use `tmux` for the
first one; in other tabs `tmux attach` picks a session no tab shows yet.

| Pane was running | Restored as |
| --- | --- |
| a shell | a shell in the same directory |
| `nvim …` | the same `nvim …` command |
| `claude …` | `claude --continue` (last conversation in that directory) |
| `codex` | `codex resume --last` (last session in that directory) |
| anything else | a shell in its directory |

- **Restart more programs:** add them to `@resurrect-processes` (e.g. `"npm run dev"`,
  `"~server->go run ."`); see the resurrect docs on restoring programs.
- **Save interval:** `@continuum-save-interval` in minutes (`0` turns autosave off).
- **No auto-restore:** `set -g @continuum-restore 'off'`, then restore with `Ctrl+B Ctrl+R`.
- **Saves** live in `~/.local/share/tmux/resurrect` (`last` points to the newest); older
  files can be deleted. **Plugins** live in `~/.local/share/tmux/plugins`, outside the repo:
  `make tmux` installs them, `make update-tmux` updates them.

## Ghostty

`.config/ghostty/config.ghostty` — theme Catppuccin Mocha, JetBrains Mono 13 (bundled with
Ghostty, no font install needed), 75% background opacity, left Option as Alt, `Cmd+K`
clearing the screen (also inside tmux), shell integration, large scrollback, desktop notifications from programs (used by Claude Code
and Codex; on macOS allow Ghostty in System Settings → Notifications). macOS-only keys
are ignored on Linux.

Change any key and reload with `Cmd+Shift+,` (or restart Ghostty). List options with
`ghostty +show-config --default --docs`, themes with `ghostty +list-themes`, fonts with
`ghostty +list-fonts`. Keep Neovim/tmux colors consistent if you change the theme
(`nvim/…/plugins/catppuccin.lua`, tmux Appearance section).

## conda

`.condarc`: conda-forge only (mirrored via prefix.dev), auto-activates the `dev` env, no
prompt prefix (Powerlevel10k shows the env).

- **Different default env:** change `default_activation_env`.
- **No auto-activation:** `auto_activate: false`.
- **Env contents:** [`packages/conda/`](../packages/README.md#conda-environments).

## Claude Code

`.claude/settings.json` is linked (per-file, so logins, history and projects in `~/.claude`
stay local). It sets the model, effort levels, enabled plugins (Go, Python, TypeScript, Lua
language servers), theme and editor mode.

- **Notifications:** `"preferredNotifChannel": "ghostty"` sends desktop notifications
  through Ghostty when Claude needs permission or input (also from background tmux windows).
- **Permissions:** `permissions.allow` pre-approves read-only commands (`git status/diff/log/show/blame`,
  `docker ps/info`) and `go test` / `go vet`. Add rules as `Bash(<prefix>:*)`; avoid commands
  that can write or run arbitrary code (`git branch` deletes, `fd -x` executes).
- Edit the file to change settings; it is the repo copy.
- Add global instructions for every project with `~/.claude/CLAUDE.md`: create it as
  `home/claude/.claude/CLAUDE.md` and run `make link` to link and track it.
- Automations on events (formatting after edits, custom notifications, …) go in a `hooks`
  section; see Claude Code's hooks documentation.

## Codex

Nothing is linked: Codex writes trusted projects, plugin paths and other state into
`~/.codex/config.toml`, so the repo only provides a starting version. A starting version is seeded once from
[`setup/templates/codex/config.toml`](../setup/templates/codex/config.toml) by `make agents`; edit the
template to change what new machines start with.

The template turns on desktop notifications through Ghostty when a turn ends or Codex
needs approval while its pane isn't focused:

```toml
[tui]
notifications = true
notification_method = "osc9"
notification_condition = "unfocused"   # or "always"
```

## bin

Scripts linked into `~/.local/bin` (on `PATH` via `.zprofile`):

| Script | Purpose |
| --- | --- |
| `tmux-sysinfo` | `Load 1.23 \| Battery 87%` for the tmux status bar (macOS + Linux). |

**Add a script:** put it in `bin/.local/bin/`, `chmod +x`, `make link`. Use `#!/bin/sh` or
`#!/usr/bin/env bash` and keep it working on both OSes; `make lint` checks it with shellcheck.
